# Site 공정 캘린더를 공종별로 · 공정표 위로 — 기획서

> 사용자 확인을 받은 뒤에 개발을 시작한다.

- 상태: 끝남 · 우선순위 1 · 예상 1일 · 영향: 웹만 (Site)

## 1. 왜 하나
- 캘린더에 공정 이름이 너무 많아 복잡하다. "무슨 공종 며칠"만 보이면 한눈에 들어온다.
- 캘린더를 공정표 위에 두고, 두 화면이 서로 맞물려 움직이면 좋다.

## 2. 무엇을 만드나
1. 현장 머리의 기간: 착공일·준공일을 큰 글씨로 따로 보여 주고, 버튼 이름 "기간 고치기" → "수정".
2. 공정 캘린더를 공정표 위로. 공정표와 연동 (표를 고치면 캘린더가 바로 바뀌고, 캘린더에서 하는 일은 표에도 바로 반영).
3. 캘린더 막대는 "공종 며칠" 만 (예: 목공사 5일, 공종 상세 이름 없음). 색은 공종마다 하나.
4. 이번 주 막대는 색을 채우고, 지난주·다음 주 막대는 속을 비우고 같은 색 점선 테두리.

## 3. 사용자가 정한 것
- 캘린더 = 보기 + 공종 통째로 옮기기 (넣기·늘리기·지우기는 공정표에서만)
- 며칠 = 그 공종 공정이 있는 날만

## 4. 바꿀 파일: `public/site.js`, `public/site.css`, `tools/test/e2e-site.cjs`, `README.md`, `RELEASE-NOTES.md`
## 5. 조심할 점: 공종 통째 옮기기는 그 공종의 모든 공정을 같이 옮기므로 바뀐 칸(start/end/plus/minus)만 저장. 공종 없는 공정은 "기타" 로 묶음.
## 6. 확인 방법: 캘린더가 표 위에 있음 · 막대에 공종+일수만 · 이번 주만 채움 · 표↔캘린더 연동 · 시험 통과
## 7. 일정표: 기획서 확인 → 개발 → 시험·검토 → 배포 (모두 11-27~28)
