# Site 공정표를 표 모양으로 (회사 공정표 양식처럼) — 기획서

> 사용자 확인을 받은 뒤에 개발을 시작한다.

- 상태: 하는 중
- 우선순위: 1 · 예상 기간: 1~2일
- 영향: 웹만 (Site 화면) → 버전 그대로, 릴리즈 노트 `## 웹`

## 1. 왜 하나 (목적)
- 지금 4주 캘린더는 막대에 색이 많아서 오히려 정신이 없다.
- 회사에서 쓰는 공정표(INTERIOR PROGRESS SCHEDULE) 양식처럼 **한 줄 = 공정 하나**, 그 줄의 날짜 칸을 **회색으로 칠하는** 표가 보기 쉽다.

## 2. 무엇을 만드나 (범위)
- 할 것:
  - 공정 목록과 날짜 칸을 한 표로 합침: 왼쪽 **공종**(예: 목공사) · **공종 상세**(예: 벽체 MDF 마감판넬 작업), 오른쪽 날짜 칸(월·일·요일·기간 번호).
  - 일정이 있는 날은 회색 칸. 오늘 줄 표시, 토요일 파랑·일요일/공휴일 빨강 글자.
  - 공정에 **공종** 칸 추가 (공종별로 묶어서 보여 줌, 공종 칸은 세로로 합쳐 보임).
  - 기본 공정 목록을 첨부 공정표의 공종·공종 상세(약 37개)로 바꿈.
  - "표준 공정 넣기": 첨부 공정표의 날짜(착공 1일째~36일째)를 **착공일 기준**으로 넣는 버튼. 첨부 현장은 착공일 11/2 로 넣으면 PDF 와 같은 날짜가 됨.
  - 끌기 방법(같은 기능은 하나로): PC 는 빈 칸을 끌어 칠하기 = 일정 넣기, 회색 칸 묶음을 끌기 = 옮기기, 끝을 끌기 = 늘리기·줄이기, ✕ = 지우기, 칸 누르기 = 그날 쉬는 날 켜고 끄기.
  - 진행률·오늘 공정·출근은 그대로.
- 안 할 것:
  - 회사 현장 이름·실제 일정을 저장소(공개)에 넣지 않음. 실제 날짜는 사이트에서 버튼으로 넣는다.
  - 4주 캘린더는 없앰 (표 하나만).

## 3. 화면·사용 방법
- 날짜 칸 = **공사기간 전체** (착공일~준공일, 주간 스케줄의 공사기간). 길면 옆으로 밀어 봄. 이번 주·오늘 칸 표시.
- 왼쪽 **공종 묶음 칸** (세로로 합친 칸, PDF 의 빨간 동그라미).
- **준공일 빨간 세로줄** + "준공" 글자.
- **A4 가로 한 장 인쇄** (인쇄 버튼, 공사기간이 길면 글자·칸을 줄여 한 장에).
- **휴대폰도 같은 표** (옆으로 밀어 보기, 칸 누르기로 넣기/켜고 끄기).
- 실제 날짜: "표준 공정 넣기" 버튼 → 착공일 고르기 → PDF 와 같은 날짜로 채움.
- 비고 칸은 넣지 않음.

## 4. 어떻게 만드나 (바꿀 파일)
- `public/site.js`: 캘린더 → 표(공종·상세·날짜 칸), 칸 끌기, 표준 공정 넣기.
- `public/site.css`: 표 모양 (엑셀 양식처럼 얇은 선, 회색 칸, 공종 칸 합치기).
- `public/site-core.js`: 기본 공정 목록(공종·상세·표준 날짜).
- `firebase/database.rules.json` + `rules.test.mjs`: 공정에 `cat`(공종) 값 허용.
- `tools/test/e2e-site.cjs`: 새 표 화면 시험으로 바꿈.
- `README.md`, `RELEASE-NOTES.md`.

## 5. 조심할 점
- 데이터: 이미 넣은 공정은 그대로 둔다. 공종이 없는 공정은 "기타" 묶음으로 보여 줌 (지우거나 덮어쓰지 않음). 바뀐 칸만 저장.
- "표준 공정 넣기"는 공정이 이미 있으면 덮어쓸지 묻고, 같은 이름만 날짜를 바꾸고 나머지는 추가.
- 보안: 첨부 PDF 의 현장 이름은 어디에도 커밋하지 않는다.
- 날짜 칸이 많아 휴대폰에서는 옆으로 밀어 보기.
