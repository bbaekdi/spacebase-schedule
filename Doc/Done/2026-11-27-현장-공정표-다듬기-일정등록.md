# Site 공정표 다듬기 · 일정 등록 · 3주 캘린더 — 기획서

> 사용자 확인을 받은 뒤에 개발을 시작한다.

- 상태: 끝남
- 우선순위: 1 · 예상 기간: 1일
- 영향: 웹만 (Site·홈·Band 화면) → 버전 그대로, 릴리즈 노트 `## 웹`

## 1. 왜 하나 (목적)
- 공정표가 좁아 보인다. 착공·준공이 바뀌면 고칠 수 있어야 한다.
- 출근 등록은 안 쓰기로 했고, 대신 현장 일정을 회사 일정에 올리는 버튼이 필요하다.
- 표 아래에 지난주·이번 주·다음 주 캘린더가 한 번 더 있으면 보기 쉽다.

## 2. 무엇을 만드나 (범위)
1. 공정표를 오른쪽 끝까지 넓힘 (지금은 최대 폭 1240px 로 막혀 있음 → 화면 폭 전체).
2. 착공일·준공일 고치기 (아래 질문 답에 따라 저장 위치 결정).
3. 출근 기능 없앰 + "일정 등록" 버튼 (아래 질문 답에 따라 올릴 곳·내용 결정).
4. 표 아래에 3주(지난주·이번 주·다음 주) 캘린더 다시 만듦. 기능은 이전 4주 캘린더와 같게: 막대 끌어 옮기기·끝 끌어 늘리기·✕ 지우기·날짜 누르기(그날 켜고 끄기)·일정 없는 공정은 목록에서 끌어 넣기.
- 안 할 것: 이미 쌓인 출근 기록 삭제 (보관만).

## 3. 사용자가 정한 것
- 착공·준공 = 주간 스케줄 공사기간도 같이 바뀜
- 일정 등록 = 회사 캘린더에 바로 (네이버 밴드에는 직접 못 올림), 공사기간 한 건
- 출근 = 전부 없앰 (기록은 보관)

## 4. 바꿀 파일 (예정)
- `public/site.css`, `public/site.js`, `public/site-core.js`, `public/portal.html`(홈 카드), `public/band.js`(출근 게시판), `firebase/database.rules.json` + `rules.test.mjs`, `tools/test/e2e-site.cjs`, `README.md`, `RELEASE-NOTES.md`.

## 5. 조심할 점
- 주간 스케줄 데이터(데스크톱 앱도 같이 씀)는 함부로 덮어쓰지 않는다. 바뀐 칸만 저장.
- 밴드(네이버)에는 사이트가 직접 글을 올릴 수 없다 (밴드 쪽 허용 없음). 가능한 방법만 쓴다.
- 이미 쌓인 출근 기록·Band 출근 글은 지우지 않는다.
- 같은 기능은 한 가지 방법만 — 표와 캘린더가 같은 데이터를 고치므로 "넣기"는 한쪽(캘린더 목록 끌기)만 하게 할지 확인.
