# 현장 공정 스케줄표 + 출근 등록 (Site) — 기획서

- 상태: **하는 중** (2026-11-25 기획서 확인, 1~4단계 만듦 → 시험 사용 대기) · 우선순위: Band 다음 · 예상: 약 2주
- 영향: 웹사이트 (새 메뉴 Site). 데스크톱 앱·주간 스케줄 화면은 안 바꿈 → 앱 버전 그대로.
- 참고: 사용자가 보내 준 현장 관리 서비스 화면(현장 목록 + 이번 주 공정 칸). 모양을 그대로 베끼지 않고 우리 주간 스케줄·Band 와 이어지게 만든다.

## 1. 왜 하나 (목적)
- 지금은 현장이 착공되면 현장 소장님이 **그날 무슨 공정인지 볼 곳이 없다.** 출근하면 네이버 밴드에 일정만 등록한다.
- 현장마다 **공정 스케줄표**를 만들고, 소장님이 **출근 등록**을 하면 Band 에 자동으로 남게 한다.

## 2. 무엇을 만드나 (범위) — 2026-11-25 사용자 답변
### 할 것
1. 상단 메뉴 **Site** (Home / Weekly Schedule / Calendar / Band / Site). 구글 로그인 회원만.
2. **현장 목록 = 주간 스케줄 PROJECT 구분 현장**. 오늘이 **공사기간 안**(착공 7일 전부터)인 현장은 "진행 현장", 끝난 현장은 "지난 현장"으로 따로.
3. **현장 소장 = 주간 스케줄 "시공 담당"** (약칭 → 직원표 이름 → 회원). 따로 정할 필요 없음.
4. **공정 스케줄표** (현장마다)
   - 공정 항목: 기본 목록(철거·설비·전기·목공·타일·도장·도배·가구·조명·청소·검수)을 넣고 현장마다 빼거나 더하기, 순서 바꾸기.
   - 일정: 공정마다 **시작일~끝일**(달력, 일요일·공휴일 빨강/토요일 파랑) + **이번 주 칸을 눌러 하루씩 더하기/빼기** (예: 목공 쉬는 날).
   - 보기 두 가지: **이번 주 칸**(공정 × 요일, ‹ › 로 주 이동) + **전체 기간 막대**(착공~준공).
   - **완료 체크** → 현장 **진행률(%)** 자동 (완료한 공정 수 / 전체).
   - 수정: **그 현장 소장님 + 관리자**. 다른 직원은 보기만.
5. **출근 등록**: 그 현장 소장님만, **버튼만**(누른 시간 기록), 하루 한 번. 출근만(퇴근 없음).
   - 출근하면 Band 새 게시판 **"출근"**에 "○○○ 출근 · 08:12 · [현장]" 글이 자동으로 올라감. (출근 글은 새 글 알림 안 보냄)
   - 이번 주 칸 위에 출근한 날 표시.
6. 홈에 **"오늘 내 현장"** 카드: 내가 소장인 진행 현장마다 오늘 공정 + 출근 버튼(출근했으면 "출근 08:12").
7. 현장 화면 머리: 현장 이름, 공사기간, 진행률, 오늘 공정, 다음 공정(D-n), 숫자 카드(진행 현장 수 · 이번 주 공정 · 진행률).

### 안 할 것 (이번엔)
- 정산·영수증, 퇴근, 위치 확인, 출근 사진, 아침 알림, 협력업체 인원 기록 → 필요하면 나중에 따로.
- 주간 스케줄 표에 공정을 자동으로 칠하기 (따로).

## 3. 화면 (글로)
- **Site 왼쪽**: 진행 현장 목록(현장 이름 + 진행률), 아래 "지난 현장" 접기. 휴대폰에서는 위쪽 고르기 칸.
- **Site 오른쪽**: 현장 머리(이름·기간·진행률·오늘/다음 공정·[출근] 버튼) → 숫자 카드 → **이번 주 공정 칸** → **전체 기간 막대** → 공정 목록(수정 화면: 이름·기간·완료·순서·삭제, "기본 목록 넣기", "공정 추가").
- **홈**: "오늘 내 현장" 카드.
- **Band**: 게시판에 "출근" 추가.

## 4. 어떻게 만드나 (바꿀 파일)
| 할 일 | 방법 |
|---|---|
| 화면 | 새 `public/site.html`, `site.js`, `site.css`, 메뉴는 `ws-common.js` |
| 현장 목록·소장 | 주간 스케줄 데이터(`spaces/<자리>/data/projects`, `groups`, `members`)를 읽기만 함 (고치지 않음) |
| 공정·출근 저장 | Firebase 새 자리 `site/<현장id>/tasks/<공정id>` {name, order, start, end, plus{날짜}, minus{날짜}, done, by, at}, `site/<현장id>/attend/<날짜>/<uid>` {name, at} |
| 규칙 | `firebase/database.rules.json` 에 site 추가 (회원만 읽기·쓰기, 형식 검사) + 시험 |
| 출근 글 | Band `board/posts` 에 cat `attend` 추가 (규칙·게시판 탭·알림 제외) |
| 홈 카드 | `portal.html` |
| 공사기간 읽기 | 주간 스케줄과 같은 방식("12.05-01.22", "10/26-12/7", "27.01.02-")을 Site 에서도 읽음 |

## 5. 조심할 점
- **주간 스케줄 데이터는 읽기만** 한다. (여러 직원이 같이 쓰는 실사용 데이터)
- 소장님 판별은 "시공 담당" 약칭 → 직원표 이름 → 회원 이름으로 잇는다. 이름이 다르면 소장으로 안 잡힘 → 회원 관리에서 이름 연결을 직원표와 같게.
- 수정 권한(소장·관리자)은 **화면에서** 막는다. Firebase 규칙은 "회원만 + 형식 검사 + 누가 고쳤는지 기록"까지 (주간 스케줄의 시공 담당을 규칙이 읽기 어려움). 회원은 초대받은 직원뿐이라 이 정도로 정함.
- 휴대폰에서 칸이 작으므로 이번 주 칸은 가로로 밀어 보기.
- 공개 저장소: 현장 이름·직원 이름은 코드·문서에 안 씀. 시험은 가짜 데이터로.
